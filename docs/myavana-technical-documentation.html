MYAVANA Hair Journey Platform and Plugin Architecture

Detailed technical reference for the production-ready MYAVANA Hair Journey experience, including page architecture, shortcode composition, data storage, authentication, AI integrations, community systems, gamification, and deployment behavior.

What This Document Covers

Source Audit Basis

This documentation is derived from the plugin source itself, centered on myavana-hair-journey.php, includes/, actions/, and the page/partial templates under templates/.

Primary architectural style: shortcode-driven WordPress application with modular PHP templates, AJAX-heavy workflows, user-meta backed journey state, custom social/gamification tables, and branded frontend bundles.
System Snapshot

Platform Summary

Production Ready

The MYAVANA Hair Journey platform is implemented as a feature-rich WordPress plugin that turns a standard WP site into a logged-in hair wellness application. The plugin owns the customer-facing product surface, authentication modal, onboarding, journey logging, goal/routine management, unified profile, AI features, community feed, and internal intelligence dashboards.

6 Core primary pages in the user-facing experience: Home, My Timeline, Profile, Community, Goals, Routines.
20+ Shortcodes registered to map feature surfaces into pages and reusable containers.
3 Major storage models: WordPress posts/meta, user meta, and custom Myavana tables.
4 Primary interaction pillars: Journey, AI, Community, Gamification.
Core architectural decision: the plugin deliberately mixes modern application behavior with WordPress-native primitives. Journey entries are persisted as a custom post type, long-lived personalized state sits in user meta, and high-volume or relational features such as social activity and gamification are stored in dedicated custom tables.

Bootstrap

Plugin Entry Architecture

The plugin bootstraps from myavana-hair-journey.php. This file registers the plugin, loads supporting includes/actions/templates, instantiates the main application class, and coordinates page creation, script loading, navigation, protection rules, and legal page seeding. 

Plugin file
  ├─ loads includes/ (auth, AI, data, analytics, errors, social, gamification)
  ├─ loads actions/ (entries, goals/routines, community, insights, dashboard handlers)
  ├─ loads templates/ page shortcode implementations
  ├─ instantiates Myavana_Hair_Journey
  ├─ activates default pages on plugin activation
  ├─ registers shortcodes on init
  ├─ enqueues global + page-specific assets
  ├─ renders navigation, preloader, mobile tabs
  └─ enforces access and logout behavior
Bootstrap Concern Implementation Observed Behavior
Main runtime class Myavana_Hair_Journey Central orchestrator for hooks, activation, assets, navigation, and protected route behavior.
Activation register_activation_hook(..., activate) Creates baseline profile table and seeds default pages containing shortcodes.
Page seeding get_default_pages() Creates Login, Register, Profile, Timeline, Goals, Routines, Add Entry, Try-On, Hair Insights, Privacy, and Terms pages.
Legal page safety maybe_seed_legal_pages() Ensures privacy and terms pages exist for active admin sessions even if activation-time creation was missed.
Protected routes template_redirect enforcement Restricts authenticated app surfaces to signed-in users while preserving a guest-facing homepage/auth path.
Logout behavior logout_redirect filter Redirects users back to the site homepage instead of a stock WP login endpoint.

Identity

Authentication and Onboarding

Authentication Runtime

includes/myavana-auth-system.php encapsulates the auth stack.

  • Admin settings page for modal behavior, onboarding, auto-approval, and Google auth
  • Frontend auth modal injected via wp_footer
  • AJAX handlers for standard auth, Google auth, password reset, onboarding save/step/skip/reset, and onboarding triggers
  • Rewrite-backed password reset route handling
  • Registration hooks and login hooks for onboarding state management

Google Auth Model

  • Configured as a web client ID in plugin settings
  • Uses Google Sign-In through frontend JavaScript origin validation, not a redirect URI callback flow
  • Server endpoint: myavana_google_auth
  • Onboarding can trigger after Google registration/sign-in for pending users
  • Designed to keep users in the MYAVANA modal flow instead of WP login screens
1
Guest lands on Home or other enabled surface and the auth modal system is eligible to render.
2
User signs in via email/password or Google Sign-In from the branded modal.
3
Server validates user state, creates or locates the account, and returns onboarding trigger state.
4
Onboarding persists hair profile and preference data through AJAX step handlers.
5
User is redirected into the app surface with first-entry launch support and homepage-safe logout behavior.
Default behavior as audited: onboarding is enabled by default when no explicit option override exists, and Google auth has been integrated into the same onboarding-aware auth lifecycle as native registration.

Entry Flow

Hair Journey Entry Lifecycle

Entries are the central unit of the platform. They are stored as WordPress posts of type hair_journey_entry and enriched through post meta plus attachment relationships for images and video.

1
User opens the create offcanvas from My Timeline, onboarding handoff, or contextual action buttons.
2
Client validates only the intended lightweight requirements: title plus at least one image or video.
3
Form serializes explicit payload keys and sends action=myavana_entry_action to admin-ajax.php.
4
Server dispatches add vs update, creates/updates the post, processes attachments, sets thumbnail/gallery/video meta, and persists extra fields.
5
Timeline cache/state refreshes, the offcanvas closes, and gamification totals may be updated.
Layer File(s) Responsibility
Form UX templates/pages/partials/create-offcanvas.php Multi-tab entry form, previews, validation, explicit payload assembly, and submit interception.
Dispatch actions/hair-entries.php myavana_handle_entry_action() routes add vs update by presence of entry_id.
Create / update persistence templates/hair-diary-timeline-shortcode.php Holds the active myavana_add_entry() and myavana_update_entry() implementations used by the dispatcher.
Modular timeline forms assets/js/timeline/timeline-forms-new.js Secondary timeline module that cooperates with HJN-owned forms and avoids duplicate submit binding.
Current validated create rule: the front end and server were aligned so that manual entry creation requires a title and at least one uploaded image or video. Rating is optional and no longer blocks creation.
Structured Planning

Goals and Routines Subsystems

Goals

  • Stored in user meta key myavana_hair_goals_structured
  • Managed through actions/goal-routine-handlers.php
  • Fields include title, description, category, priority, start/target dates, progress, measurement values, milestones, and notes
  • Progress milestone rewards are issued at 25/50/75/100 percent thresholds
  • Goal pages normalize categories, metrics, and status for a premium management dashboard

Routines

  • Stored in user meta key myavana_current_routine
  • Completion history stored in myavana_routine_completions
  • Routines page computes normalized frequency classes such as daily, twice weekly, bi-weekly, monthly, and as needed
  • Supports reminder-day aware due-today logic and rolling completion analysis
  • Timeline and routines page share the same backing state, allowing direct cross-surface consistency
User Meta Backing
  myavana_hair_goals_structured   -> array of structured goal records
  myavana_current_routine         -> array of routine records
  myavana_routine_completions     -> map: YYYY-MM-DD => [routine_ids]

Operational Pattern
  form submit -> AJAX handler -> sanitize / normalize -> update user meta -> optional reward check

AI Layer

AI, Recommendations, and Generated Media

Gemini-Based Services

  • Myavana_AI is the core AI service wrapper
  • Image preview model: gemini-2.0-flash-preview-image-generation
  • Text/vision analysis model: gemini-2.0-flash
  • API keys are read from WordPress options, not hardcoded constants
  • Daily per-user usage caps are enforced via user meta counters

AI Capabilities in Product

  • Hairstyle preview generation from uploaded images
  • Comprehensive hair analysis from photo input
  • Auto-generated journey entries from AI analysis paths
  • Insight summaries in profile and analytics surfaces
  • AI-assisted product/style metadata extraction
Implementation note: generated AI results do not live only as transient UI artifacts. The system can persist relevant analysis output back into post meta, user profile snapshots, and journey history, which is critical for longitudinal progress views and recommendation continuity.

Security

Security and Reliability Patterns

Concern Observed Pattern Why It Matters
AJAX authorization Nonce verification is used broadly across auth, journey, goals, routines, profile, and admin handlers. Prevents cross-site request forgery on mutation endpoints.
Input sanitation Use of sanitize_text_field, sanitize_textarea_field, integer bounds, and structured normalization. Reduces malformed payloads and unsafe persistence.
User ownership checks Entry update handlers verify post authorship; goal/routine handlers read from current user meta only. Prevents cross-user modification of personalized data.
Route protection Logged-in-only app pages return sign-in prompts or are protected during redirect handling. Protects personal journey and community management surfaces.
Schema safety Custom tables are created through dbDelta; some systems perform runtime schema checks and repairs. Mitigates production drift across environments and plugin revisions.
Important engineering note: the codebase currently contains some legacy overlap, especially around older diary/timeline handlers and newer modular handlers. The active runtime works, but long-term maintenance will benefit from consolidating duplicated entry-related endpoints into a single canonical implementation.
